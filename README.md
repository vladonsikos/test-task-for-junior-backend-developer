# Task Service

Сервис для управления задачами с HTTP API на Go.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск

```bash
docker compose up --build
```

Сервис будет доступен по адресу `http://localhost:8080`.

Если postgres уже запускался ранее со старой схемой:

```bash
docker compose down -v
docker compose up --build
```

## Swagger

- UI: `http://localhost:8080/swagger/`
- OpenAPI JSON: `http://localhost:8080/swagger/openapi.json`

## API

Базовый префикс: `/api/v1`

| Метод  | Путь                              | Описание                              |
|--------|-----------------------------------|---------------------------------------|
| POST   | /tasks                            | Создать задачу                        |
| GET    | /tasks                            | Получить список задач                 |
| GET    | /tasks/{id}                       | Получить задачу по ID                 |
| PUT    | /tasks/{id}                       | Обновить задачу                       |
| DELETE | /tasks/{id}                       | Удалить задачу                        |
| GET    | /tasks/{id}/occurrences?from=&to= | Получить даты вхождений периодичности |

## Реализованная фича: настройки периодичности

Задача может иметь настройки повторяемости (`recurrence_settings`). Они хранятся в отдельной таблице `recurrence_settings` со связью 1:1 к `tasks`.

### Типы периодичности

| Тип              | Описание                                | Обязательные поля     |
|------------------|-----------------------------------------|-----------------------|
| `daily`          | Каждые N дней                           | `interval` (≥ 1)      |
| `monthly`        | В определённое число каждого месяца     | `day_of_month` (1-30) |
| `specific_dates` | Только на указанные конкретные даты     | `dates` (массив дат)  |
| `even_odd`       | По чётным или нечётным числам месяца    | `parity` (even/odd)   |

### Примеры запросов

**Создать ежедневную задачу (каждые 2 дня):**
```json
POST /api/v1/tasks
{
  "title": "Обзвон пациентов",
  "description": "Ежедневный обзвон",
  "status": "new",
  "recurrence_settings": {
    "type": "daily",
    "interval": 2
  }
}
```

**Задача каждое 15-е число:**
```json
{
  "recurrence_settings": {
    "type": "monthly",
    "day_of_month": 15
  }
}
```

**Задача на конкретные даты:**
```json
{
  "recurrence_settings": {
    "type": "specific_dates",
    "dates": ["2025-01-10", "2025-01-25", "2025-02-05"]
  }
}
```

**Задача по чётным дням:**
```json
{
  "recurrence_settings": {
    "type": "even_odd",
    "parity": "even"
  }
}
```

**Получить даты вхождений за месяц:**
```
GET /api/v1/tasks/1/occurrences?from=2025-01-01&to=2025-01-31
```

**Удалить настройки повторяемости при обновлении:**
```json
PUT /api/v1/tasks/1
{
  "title": "...",
  "status": "new",
  "remove_recurrence": true
}
```

## Принятые решения

### Подход к реализации периодичности

ТЗ говорит «задачи создавались с учётом настроек периодичности». Это можно реализовать двумя способами:

1. **Хранить настройки + вычислять даты по запросу** — выбранный подход
2. Автоматически создавать копии задач по расписанию (cron)

Выбран вариант 1, потому что:
- Одна запись в БД вместо сотен дублей
- Фронтенд получает даты через `GET /occurrences` и отображает задачу в нужные дни
- Легко менять настройки без удаления всех созданных копий
- Нет фоновых процессов, нет race conditions



Настройки периодичности вынесены в `recurrence_settings` (не JSONB), потому что поля строго типизированы, легко добавлять индексы по `type` и `day_of_month`, связь 1:1 выражена через UNIQUE INDEX.

### Логика daily

Для `daily` с `interval=N` задача выполняется каждые N дней, считая от начала запрошенного диапазона (`from`). Например, `interval=3` за январь даёт 1, 4, 7, 10... января.

### Граничный случай: 31-е число

Тип `monthly` поддерживает числа 1–30. 31-е исключено — не все месяцы его имеют.

### Диапазон для occurrences

Эндпоинт `GET /occurrences` ограничен диапазоном в 1 год.

### Удаление периодичности

`remove_recurrence: true` — удаляет настройки. `recurrence_settings: null` — оставляет без изменений.
